## Найденные дефекты — исправлены

### 1. Операционные алерты молча теряются в первые минуты после старта (высокий)

`app/services/alert_service.py`

```python
previous = _last_sent.get(event, 0)          # ← 0 вместо «ещё не отправляли»
if now - previous < settings.alert_min_interval_seconds:
    return False
```

`time.monotonic()` считает время от старта хоста. Пока uptime меньше `ALERT_MIN_INTERVAL_SECONDS` (по умолчанию 300 с), условие `now - 0 < 300` истинно, и **первый алерт каждого типа отбрасывается**. Именно в этот момент (перезапуск, crash-loop, первые минуты после деплоя) алерты нужнее всего, а `api_unhandled_error` / `readiness_failed` / `diagnosis_jobs_recovery_exhausted` уходят в никуда.

Симптом обнаружился сам: `tests/test_monitoring.py` падал на freshly booted машине (uptime 175 с) и проходил на машине с uptime > 300 с — то есть тест был нестабильным из-за бага в коде, а не наоборот.

**Исправление:** отсутствующая запись больше не считается «отправленной в момент ноль»; добавлен регрессионный тест с подменой `monotonic()` на малое значение.

### 2. CSV-импорт товаров отдавал 500 вместо 422 (средний)

`app/catalog.py`, `POST /api/v1/partner/products/import/csv`

Файл до 2 МБ разрешён, но лимит поля модуля `csv` по умолчанию — 128 КБ. Одно длинное поле → `_csv.Error: field larger than field limit`. `csv.Error` **не является** `ValueError`, а обход `DictReader` находился вне `try`, поэтому исключение пробрасывалось наружу: HTTP 500, срабатывал operational alert, клиент получал «Не удалось обработать запрос» вместо понятной ошибки валидации. Воспроизведено тестом до исправления.

**Исправление:** валидация строки вынесена в `_csv_row_payload()`, обход ридера обёрнут в обработку `csv.Error` → 422 с номером строки. Добавлена проверка в существующий тест партнёрского кабинета.

### 3. Утечка blob-URL в веб-клиенте (низкий)

`web/app.js`: `state.objectUrls` пополнялся в `renderPhotoSelection()` и `photoBlobUrl()`, но **никогда не читался и не освобождался** — `URL.revokeObjectURL` для этих URL не вызывался нигде. Каждое превью загрузки и каждая миниатюра в истории держали blob в памяти до перезагрузки страницы.

**Исправление:** добавлен `resetObjectUrls()`, вызываемый перед перерисовкой превью, перед перерисовкой истории растения и при выходе из аккаунта.

Все три исправления покрыты тестами, `ruff check` чист, полный прогон — 118 passed. Коммит `eb98161`, отправлен в `arena/01a0e8f9-ai-garden`.

## Рекомендации (не менял — требуется решение)

### Высокий приоритет

1. **Rate limit через Redis: новое соединение на каждый запрос и неатомарный INCR/EXPIRE.**
   `app/services/rate_limit_service.py` в celery-режиме вызывает `Redis.from_url(...)` на каждый вызов — то есть на каждый login/register/upload открывается новое TCP-соединение (лишний RTT и сокеты под нагрузкой). Кроме того, `INCR` и `EXPIRE` идут двумя отдельными командами: если процесс упадёт между ними, счётчик останется без TTL и **пользователь будет заблокирован навсегда** (до ручной очистки ключа).
   → Клиент уровня модуля с пулом соединений + `pipeline()` (MULTI) для `INCR`/`EXPIRE`.

2. **`generate_due_notifications` загружает все ключи дедупликации в память.**
   `existing = set(db.scalars(select(UserNotification.deduplication_key)))` — линейный рост; при миллионе уведомлений hourly-задача съест память. → Уникальный индекс по `deduplication_key` + проверка батчами (`WHERE key IN (...)`) и отлов `IntegrityError`, либо `INSERT ... ON CONFLICT DO NOTHING`.

### Средний приоритет

3. **Неограниченный кэш погоды.** `WeatherService._cache` растёт бесконечно (ключ — `язык:локация`), очистки нет. → LRU с ограничением размера + периодическая чистка по истечении TTL.

4. **N+1 при семантическом поиске по знаниям (PostgreSQL).** В `_retrieve_from_database` после `order_by(cosine_distance).limit(limit*4)` для каждого чанка выполняется отдельный `SELECT` ради значения близости — до 16 дополнительных запросов на каждый анализ. → Вынести расстояние в столбец первого запроса (`select(KnowledgeChunk, KnowledgeChunk.embedding.cosine_distance(...))`).

5. **`POST /api/v1/auth/logout` без refresh-токена не делает ничего.** Если cookie потеряна, а тело не передано, сессия не отзывается и access token живёт до 30 минут. Стоит либо требовать токен, либо возвращать 400/204 с явным признаком «сессия не найдена».

6. **`FORWARDED_ALLOW_IPS="*"` в `compose.prod.yaml`** вместе с `--proxy-headers`. Если перед Caddy появится ещё один путь (LB, CDN без перезаписи заголовков), `X-Forwarded-For` можно подделать. → Ограничить адресом прокси/сетью Docker.

7. **Неиспользуемая dev-зависимость `httpx2==2.7.0`.** Пакет не импортируется нигде в коде; тянет за собой `httpcore2`, `truststore`. Сам проект легитимный (pydantic/httpx2), но это лишняя поверхность в dev-контуре и в `pip-audit`. → Удалить, если не закладывается миграция.

### Низкий приоритет

8. **`hash_partner_key()` — обычный SHA-256 без «соли».** Сейчас ключи выдаются как `token_urlsafe(40)` (240 бит), так что перебор нереализуем; но при утечке таблицы слабые/короткие ключи стали бы уязвимы. → HMAC с `PARTNER_ATTRIBUTION_SECRET` по образцу `_key()` в `rate_limit_service`.

9. **Схема URL алерт-вебхука не проверяется** (`urlopen` с конфигурируемым URL, bandit B310). В production включается проверка `https://`, но явная валидация схемы при старте дешевле и надёжнее.

10. **`request_body_limit` учитывает только `Content-Length`.** Запросы с chunked transfer-encoding без этого заголовка проходят мимо; сейчас их сдерживают лимиты чтения внутри эндпоинтов (10 МБ на фото, 2 МБ CSV), но middleware не соблюдается как единая граница.

11. **`downloadAuthenticatedFile()`:** `URL.revokeObjectURL(url)` вызывается сразу после `link.click()`, и ссылка не добавляется в DOM. В Firefox это может отменить скачивание. → Добавлять/удалять элемент и отзывать URL в `setTimeout`.

12. **Нет `pyproject.toml`** — нет конфигурации `ruff`/`pytest`, а `ruff format --check` сообщает о 50 неотформатированных файлах (CI форматирование не проверяет). → Добавить `[tool.ruff]` и, при желании, шаг `ruff format --check` в CI, чтобы стиль не расходился.

## Что сделано хорошо

- **Изоляция данных.** Все пользовательские сущности достаются через join до `Garden.user_id`; партнёрские — через `PartnerMember.partner_id`. IDOR-сценарии покрыты тестами (`test_users_cannot_access_each_others_gardens`, `test_rejects_foreign_photo`, `test_partner_cabinet_isolated_products_leads_and_roles`).
- **Сессии и токены.** Ротационные refresh-токены с хранением хеша, одноразовые previous-hash для детекта повторного использования, отзыв всех сессий при сбросе пароля/блокировке, проверка `revoked_at` при каждом запросе.
- **Атрибуция и деньги.** Подписанный HMAC click ID, отдельный ротируемый partner key с хешем, идемпотентные лиды, подтверждение конверсии администратором, неизменяемые снимки счетов + SHA-256 PDF + проверка байт при чтении, журнал `AdminAuditLog`.
- **Работа с файлами.** Реальная санитизация изображений (пересохранение, проверка формата/размеров/кадров, decompression bomb), приватное S3/local-хранилище вне корня, outbox-удаление с ретраями.
- **AI-безопасность.** Обезличенный HMAC-идентификатор вместо user id, `store=False`, фильтрация source_ids по проверенному каталогу, детерминированная политика safety и аудит изменений, жёсткая схема ответа.
- **Инфраструктура.** Зависимости закреплены с хешами, `pip-audit` и `alembic check` в CI, prod-компоуз требует все секреты через `${VAR:?}`, отдельные worker/beat, непривилегированный пользователь в контейнере, CSP и security-заголовки, локализация ошибок без утечки русского текста в EN/LV.
- **Клиент.** Ни одного `innerHTML`/`eval`: только `textContent` и `createElement`, CSP `default-src 'self'`.
- **Честность про качество.** `evals/` намеренно пуст и блокирует релиз до появления 200 экспертно размеченных случаев.

## Пробелы в покрытии

- E2E (Playwright) покрывает только путь садовода; админская панель, кабинет партнёра и инвойсы проверяются только на уровне API.
- Нет негативного теста на `POST /api/v1/auth/logout` без токена (см. п. 5).
- Локально невозможно проверить `alembic check` и `pip-audit` (нужны PostgreSQL и Python 3.12) — это делает CI.
