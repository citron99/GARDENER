## Дефекты, найденные при ревизии — исправлены

### 1. Операционные алерты молча терялись в первые минуты после старта (высокий)

`app/services/alert_service.py`: отсутствующая запись в `_last_sent` сравнивалась с `monotonic() == 0`, поэтому первый алерт каждого типа отбрасывался, пока uptime хоста меньше `ALERT_MIN_INTERVAL_SECONDS` (300 с) — то есть ровно во время перезапуска или crash-loop'а. Тест `test_monitoring` из-за этого был нестабильным: падал на свежезагруженной машине и проходил на «прогретой».

### 2. CSV-импорт товаров отдавал 500 вместо 422 (средний)

`app/catalog.py`: файл до 2 МБ разрешён, а лимит поля модуля `csv` — 128 КБ. `csv.Error` не является `ValueError` и пробивался мимо ветки валидации → HTTP 500 + operational alert вместо понятной ошибки. Валидация строки вынесена в `_csv_row_payload()`, обход ридера обёрнут в обработку `csv.Error` → 422 с номером строки.

### 3. Утечка blob-URL в веб-клиенте (низкий)

`web/app.js`: `state.objectUrls` только пополнялся, `revokeObjectURL` не вызывался никогда — каждое превью и каждая миниатюра истории держали blob в памяти до перезагрузки страницы. Добавлен `resetObjectUrls()`.

## Рекомендации из ревизии — все реализованы

### Высокий приоритет

**4. Rate limit через Redis: новое соединение на каждый запрос + неатомарный INCR/EXPIRE.**
`app/services/rate_limit_service.py`: клиент теперь создаётся один раз (`lru_cache`) и использует пул соединений; счётчик и TTL выставляются одним Lua-скриптом (`INCR` + `EXPIRE` при `count == 1`), поэтому падение между командами больше не оставляет ключ без срока жизни. Семантика окна сохранена фиксированной, как и была. Поведение при недоступности Redis не изменилось: fail-closed 503.

**5. `generate_due_notifications` загружала все ключи дедупликации в память.**
`app/services/notification_service.py`: уведомления сначала собираются в памяти, затем проверяются только ключи-кандидаты (`_persisted_keys`, батчами по 500) и вставляются одним оператором с `ON CONFLICT DO NOTHING` (PostgreSQL) / `INSERT OR IGNORE` (SQLite) — уникальный индекс по `deduplication_key` уже был в схеме, теперь он используется как защита от гонки, а не как источник 500-х.

### Средний приоритет

**6. Неограниченный кэш погоды.** `WeatherService` использует `OrderedDict` с LRU-вытеснением и очисткой просроченных записей при каждом обращении; предел задаётся новым параметром `WEATHER_CACHE_ENTRIES` (по умолчанию 256, валидируется при старте, добавлен в `.env.example`).

**7. N+1 при семантическом поиске по знаниям.** В PostgreSQL-ветке `_retrieve_from_database` расстояние теперь читается из того же запроса (`select(KnowledgeChunk, cosine_distance)` вместо отдельного `SELECT` на каждый чанк): до 16 лишних обращений к БД на каждый анализ. Проверено компиляцией выражения под диалект `postgresql`.

**8. `POST /api/v1/auth/logout` без refresh-токена ничего не делал.** Теперь ответ 204 дополняется заголовком `X-Session-Revoked: true|false`: клиент видит, была ли сессия действительно отозвана (при потерянной cookie access token иначе живёт до 30 минут). `revoke_refresh_token` возвращает признак отзыва.

**9. `FORWARDED_ALLOW_IPS="*"` в `compose.prod.yaml`.** Заменено на `127.0.0.1` и приватные диапазоны Docker (`10/8`, `172.16/12`, `192.168/16`) с возможностью переопределения через переменную окружения — `X-Forwarded-*` теперь доверяется только bundled-прокси.

**10. Неиспользуемая dev-зависимость `httpx2`.** Удалена из `requirements-dev.txt` и из `requirements-dev.lock` вместе с exclusivo-dependent `httpcore2` и `truststore`. Целостность лока проверена: `pip install --dry-run --require-hashes -r requirements-dev.lock` проходит.

### Низкий приоритет

**11. `hash_partner_key` был обычным SHA-256.** Ключ теперь хешируется через HMAC с `PARTNER_ATTRIBUTION_SECRET`. Обратная совместимость сохранена: `verify_partner_key` принимает и старый digest и при успешном postback'е прозрачно перехеширует его — партнёрам не нужно вручную ротировать ключи.

**12. Схема URL алерт-вебхука.** Добавлена проверка в `validate_runtime_settings` (http/https в любой среде) иguard в `alert_service._send`: `file://` и любые не-HTTP схемы отклоняются с записью в лог. Bandit B310 по этому месту больше не срабатывает.

**13. `request_body_limit` учитывал только `Content-Length`.** Middleware переписан на чистый ASGI (`RequestBodyLimitMiddleware`): тело считается по байтам в потоке, поэтому chunked-запросы без `Content-Length` тоже отсекаются, а лимит соблюдается как единая граница. Подтверждено на живом сервере: 70 МБ с `Transfer-Encoding: chunked` → 413, обычная multipart-загрузка → 201.

**14. `downloadAuthenticatedFile` отзывал blob URL в тот же тик.** Ссылка теперь добавляется в DOM, кликается, удаляется, а `revokeObjectURL` вызывается отложенно; тот же помощник `downloadBlobUrl` использован и для экспорта данных аккаунта.

**15. Не было конфигурации `ruff`/`pytest`.** Добавлен `pyproject.toml`: `[tool.ruff]` (target-version, line-length 120, исключения), `[tool.ruff.lint]` с явным набором правил, которые CI проверяет сегодня (`E4`, `E7`, `E9`, `F`), `[tool.ruff.format]` и `[tool.pytest.ini_options]` (`testpaths`, `pythonpath`). Набор правил намеренно оставлен прежним: расширение до `I`/`B`/`UP`/`SIM` — отдельная задача (сейчас это 80+ исправлений только по `I`).

## Что сделано хорошо

- **Изоляция данных.** Пользовательские сущности достаются через join до `Garden.user_id`, партнёрские — через `PartnerMember.partner_id`; IDOR-сценарии покрыты тестами.
- **Сессии и токены.** Ротационные refresh-токены с хранением хеша, одноразовый previous-hash для детекта повторного использования, отзыв всех сессий при сбросе пароля/блокировке, проверка `revoked_at` при каждом запросе.
- **Атрибуция и деньги.** Подписанный HMAC click ID, ротируемый partner key, идемпотентные лиды, подтверждение конверсии администратором, неизменяемые снимки счетов + SHA-256 PDF с проверкой байт при чтении, аудит в `AdminAuditLog`.
- **Работа с файлами.** Реальная санитизация изображений, приватное S3/local-хранилище вне корня, outbox-удаление с ретраями.
- **AI-безопасность.** Обезличенный HMAC-идентификатор, `store=False`, фильтрация source_ids, детерминированная safety-политика с аудитом.
- **Инфраструктура.** Зависимости закреплены с хешами, `pip-audit` и `alembic check` в CI, prod-компоуз требует секреты через `${VAR:?}`, отдельные worker/beat, непривилегированный пользователь, CSP и security-заголовки, локализация ошибок без утечки русского текста.
- **Клиент.** Ни одного `innerHTML`/`eval` — только `textContent` и `createElement`.
- **Честность про качество.** `evals/` намеренно пуст и блокирует релиз до появления 200 экспертно размеченных случаев.

## Покрытие и пробелы

- 131 тест: 118 существовавших + 13 новых в `tests/test_hardening.py` (Redis-лимит, дедупликация, кэш погоды, заголовок logout, лимиты тела, HMAC-ключи партнёра, схемы вебхука).

- Локально недоступны `alembic check` и `pip-audit` (нужны PostgreSQL и Python 3.12) — это делает CI.
